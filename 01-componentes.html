Arquitectura de componentes GCP

Vista C4/container de arquitectura objetivo. Flechas sólidas: request. Punteadas: evento, persistencia o trust. PROD clínico continúa pre-live.

Entrada

SPA obtiene token GCIP. API deriva hospital desde `firebase.tenant` + registry; request nunca elige tenant.

Procesamiento

Workloads separados: API clínica, ingesta Forms y jobs. Pub/Sub/Tasks invocan rutas internas mediante OIDC.

Persistencia

Firestore conserva metadata/fuente; GCS conserva DOCX/PDF y archivos de auditoría/backup bajo prefijo tenant.
