Modelo de datos Firestore

Una database Native por ambiente. Control plane global explícito; toda PHI vive bajo path tenant.

Relaciones principales

  • rawFormResponses.epicrisisId → epicrisis fuente.
  • documents.epicrisisId → proyección documental.
  • Epicrisis correcciones usan predecessor/origin y revisiones append-only.
  • Audit/outbox enlazan resource type/id/revision.

Consistencia

  • `schemaVersion` y exact-key codecs bloquean drift silencioso.
  • `revision` + CAS/transactions controlan concurrencia.
  • Receipts ligan intención completa mediante hashes.
  • Timestamps persistidos son server-owned.

Backup lógico incluido

memberships, professionalProfiles, invitations, epicrisis + revisions/result, rawFormResponses, documents, templates, ingestionReceipts, outbox, auditEvents, auditExports, idempotencyKeys y tenantSettings.

Backup lógico excluido

shadowReceipts, quotaReceipts, quotaWindows, formSubmissionLaunches, backupControl y backupOperations: evidencia/leases/counters efímeros u operación destino.
